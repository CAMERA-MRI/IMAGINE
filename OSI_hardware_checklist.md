## Note to Reviewers

- Please go through the checklist and provide detailed feedback that might be helpful to the project representative to justify a review score e.g. if you don't check a box, please explain what exactly is missing if appropriate.
- Each project is reviewed by at least 2 reviewers.
- If a project is being resubmitted, this is indicated with reference to the previous review report and the changes that have been made/points that were addressed.
- Mandatory requirements for projects to be published on [opensourceimaging.org](https://opensourceimaging.org/projects) are marked **in bold**.
- Open-source licenses for the project are checked beforehand by the `CAB Admin` or `CAB Editor`
- If a question is not applicable to the project, please check the box and write a short comment.
- If the hardware project contains software, please perform also the software review
- For questions and guidelines see also our CAB instructions [here](https://gitlab.com/osiiev/cab/-/blob/main/README.md).

## Scores for Hardware

### Readme

1. [ ] **Is a README file (or equivalent) available with a project description?** (1)
2. [ ] Have the design considerations been explained? (1)

### Bill of Materials

1. [ ] **Is a Bill of Materials (BoM) provided to reproduce the design?** (1)
2. [ ] Is the Bill of Materials complete/complies with our [best practices](https://gitlab.com/osiiev/cab/-/blob/main/guidelines/bill-of-materials.md)? (1)

### Source Files

1. [ ] **Are all files needed to reproduce the project according to the project description available in their native file format?** (1)

### Status of Freedom

1. [ ] Are all source files editable with open-source software (e.g. FreeCAD, KiCAD)? (1)

### Production Files

1. [ ] **Are all files needed to reproduce the project according to the project description available in a generally accessible export file format (e.g. STP, STL, GRB)?** (1)
2. [ ] Is the manufacturing environment (e.g. machine parameters) well defined or sufficiently explained to reproduce the production as intended? (1)
    > For instance, this is already given for a PCB, when complete Gerber files are provided. Then please grant this point.

### Assembly

1. [ ] **Is the assembly of the project sufficiently explained, allowing for the complete replication of the project, e.g. by an assembly guide?** (1)
    > For some projects the assembly is clearly self-explanatory or not even needed, e.g. for one-piece 3D prints. Then please grant this point. 

### Development Tracking

1. [ ] **Is a versioning scheme implemented (e.g. git repository)** (1)
2. [ ] Is an issue tracking implemented publicly? (1) 
3. [ ] Does the project have a communication space for questions, ideas, exchange with the developers or a user community? (1)

### Testing

1. [ ] Are testing routines available to evaluate the expected performance of the final design? (1)
2. [ ] Are testing routines complete (e.g. available for all subcomponents/subprocesses of the project build)? (1)

### Use

1. [ ] Is a user manual available? (1)
    > In case the intended use is clearly self-explanatory, so a manual is not needed. Then please grant this point.
2. [ ] Is a risk assessment or a safety notice available? (1)
3. [ ] Is information available (e.g. contact persons) if the project has been independently successfully replicated? (1)
